# 桌宠遥控（Android BLE 上位机）

通过手机蓝牙控制 STM32 桌面宠物的动作。对应固件 `HardWare/PetAction.c` 里的蓝牙指令表。

- 包名：`com.desktoppet.remote`
- 最低系统：Android 5.0（API 21）
- 传输：**BLE（低功耗蓝牙）**，不是经典蓝牙 SPP
- 协议：**每按一次按钮发送 1 个 ASCII 字节**，不加换行、不加回车

安装包：`DeskPetRemote.apk`（约 33 KB）

---

## 一、和官方 demo 的对应关系

本工程的 BLE 实现参考官方 `eciot_bletool_for_Android_V1.0.10_Java` 的 `ECBLE.java`，
关键参数完全一致：

| 项目 | 值 |
| --- | --- |
| 扫描 | BLE 扫描（`BluetoothLeScanner` / `SCAN_MODE_LOW_LATENCY`） |
| 连接 | `device.connectGatt(ctx, **false**, callback)`（`false` = 直接连，不等广播） |
| 服务发现 | 连上后立即 `discoverServices()` |
| **写特征值** | `0000fff2-0000-1000-8000-00805f9b34fb` |
| **通知特征值** | `0000fff1-0000-1000-8000-00805f9b34fb` |
| 写入方式 | `WRITE_TYPE_NO_RESPONSE`（无应答写） |
| 配对 | **不需要** |

> 上一版用了经典蓝牙 SPP（`createRfcommSocketToServiceRecord`），
> 对这个模块完全不适用——BLE 设备根本不会出现在"已配对设备"列表里，
> 这也是当时连不上的原因。

## 二、安装

把 `DeskPetRemote.apk` 传到手机，点击安装。首次需要在系统里允许"安装未知来源应用"。

## 三、使用步骤

1. **给桌宠上电**，模块开始广播
2. 打开 App，点右上角 **扫描**
3. 弹出列表，会实时刷出附近的 BLE 设备（名称 + 信号强度 + MAC）
4. **点一下你的设备**（通常名字里带 `EC`、`JDY`、`HM`、`AT` 之类，或者一串 MAC）
5. 状态灯变绿、显示"已连接 xxx"就可以按按钮了

**不需要去系统蓝牙里配对**，扫到直接点就连上。

扫描 12 秒后自动停止。如果列表是空的：

- 确认宠物已上电（模块指示灯在闪）
- 手机离模块 1 米以内
- 确认手机蓝牙已打开
- **Android 11 及以下**：必须打开系统"定位"开关，否则扫不到任何 BLE 设备（这是安卓的限制，不是 bug）

## 四、界面说明

按钮分 5 组，底部是发送记录（时间戳 + 指令名 + 实际字节 + 十六进制）。

| 分组 | 按钮 |
| --- | --- |
| 姿态 | 放松趴下、蹲下、直立、趴下 |
| 移动 | 前进、后退、左转、右转、摇摆、摇摆26s/27s/16s/15s |
| 特技 | 前跳、后跳、打招呼、伸懒腰、拉伸、摇尾巴 |
| 灯光与状态 | 开灯、关灯、呼吸灯开、呼吸灯关、显示电量 |
| 调速 | 走路加速、摇摆加速 |
| 天气 | 同步天气、显示天气 |

连接过程中会打印服务发现结果，如果没找到 `FFF2` 会直接报错
"没找到写特征值 FFF2，这个设备可能不是宠物模块"，可以用来排除连错设备。

| --- | --- | --- | --- | --- |

| 蹲下 | `0` | 0x30 | 30 | 压低身体 |
| 直立 | `1` | 0x31 | 31 | 站立，**同时停止一切移动** |
| 趴下 | `2` | 0x32 | 32 | 身体贴地 |
| 前进 | `3` | 0x33 | 33 | **持续前进** |

| 走路加速 | `8` | 0x38 | 38 | 循环切档 550→500→450→400→350→300ms |
| 摇摆加速 | `9` | 0x39 | 39 | 循环切档 9→8→7→6→5→4 |
| 摇尾巴 | `@` | 0x40 | 40 | **开关**，再按一次关闭 |
| 前跳 | `A` | 0x41 | 41 | 向前跳一下 |
| 后跳 | `B` | 0x42 | 42 | 向后跳一下 |
| 打招呼 | `C` | 0x43 | 43 | 挥手 |
| 开灯 | `D` | 0x44 | 44 | 点亮全部 LED |
| 关灯 | `E` | 0x45 | 45 | 熄灭全部 LED |
| 呼吸灯开 | `F` | 0x46 | 46 | 开启呼吸效果 |
| 呼吸灯关 | `G` | 0x47 | 47 | 关闭呼吸效果 |
| 伸懒腰 | `H` | 0x48 | 48 | 前腿伸展 |
| 拉伸 | `I` | 0x49 | 49 | 身体拉伸 |
| 显示电量 | `P` | 0x50 | 50 | **开关**，切换"Power:xx"显示 |
| 显示天气 | `Q` | 0x51 | 51 | 切换到天气表情（语音通道同样支持） |
| 摇摆26s | `R` | 0x52 | 52 | 摇摆 **26 秒**后自动站好 |
| 摇摆27s | `S` | 0x53 | 53 | 摇摆 **27 秒**后自动站好 |
| 摇摆16s | `T` | 0x54 | 54 | 摇摆 **16 秒**后自动站好 |
| 摇摆15s | `U` | 0x55 | 55 | 摇摆 **15 秒**后自动站好 |

> **0x52~0x55 的秒数是怎么算的**
>
> 不是靠定时器，而是数的 `Delay_ms(SwingDelay)`：一个来回 = 242 步，
> 默认 6ms/步 ≈ 1.45 秒，摇到累计时间够了就停。好处是按过「摇摆加速」
> （0x39 改 `SwingDelay`）之后秒数依然准确。
>
> 这几个不同的时长是配语音用的 —— 每条语音时长不同，摇到语音放完正好。
> 上一段里说的「动作做完等 2 秒」对这些同样生效，所以实际停留会比标称多 2 秒。

### 动作结束后的 2 秒等待

在语音通道下，一串动作做完（`Action_Mode` 回到 9 = 待机摇尾巴）之后，
固件会再停 **2 秒**才继续调度：

```c
if((ModeBefore!=9U) && (Action_Mode==9U) && (Sustainedmove==0U))
{
    Delay_ms(ACTION_TAIL_DELAY_MS);   /* Variable.h，默认 2000 */
}
```

判断依据是"进来时不是 9、出去时变成 9"，所以一串动作（比如 打招呼 → 站好 → 待机）
只会在最后停一次，不会每个动作都停。之前测试发现有些动作比语音短，动作一结束
马上干下一件事就把语音盖掉了，加这 2 秒正好补上。

**蓝牙通道不受影响**（`Sustainedmove==1`）：连续走路时中间插 2 秒会一顿一顿的。

## 六、天气功能

### 工作流程

```
手机定位 → Open-Meteo 接口 → 组 8 字节帧 → BLE 写 FFF2 → STM32 解析 → OLED 显示
```

桌宠本身不联网，天气是手机取到之后通过蓝牙下发的。蓝牙模块只是管道。

### 怎么用

1. 先连上桌宠
2. 按 **同步天气** —— App 会申请定位权限，取当前位置的天气并下发给桌宠
3. 按 **显示天气**（或对桌宠说「天气」）—— 屏幕切到天气表情
4. 底部日志会打印类似：`→ 天气 多云 24~29C 60%  帧 AA 55 04 01 40 45 3C 3C`

### 屏幕显示

```
      多云          ← 天气描述，16×16 汉字居中
温度 24~29C         ← 当天最低~最高温
湿度 60%            ← 湿度
```

温度取的是**当天的区间**（Open-Meteo 的 `daily.temperature_2m_min/max`），
不是当前时刻温度。没取到区间时退回用当前温度占位。

从没收到过天气数据时显示 `NO DATA`。

### 通信协议（手机 → 板子）

| 字节 | 含义 |
| --- | --- |
| 0 | `0xAA` 帧头 |
| 1 | `0x55` 帧头 |
| 2 | 长度 = 4（payload 字节数） |
| 3 | 天气类型 0..9 |
| 4 | 当天最低温 + 40（0x00 = -40℃，0x64 = +60℃） |
| 5 | 当天最高温 + 40（编码同上） |
| 6 | 湿度 0..100 |
| 7 | 校验 = 字节 2 ⊕ 3 ⊕ 4 ⊕ 5 ⊕ 6 |

天气类型：`0 晴 / 1 多云 / 2 阴 / 3 小雨 / 4 中雨 / 5 大雨 / 6 阵雨 / 7 雷阵雨 / 8 雪 / 9 雾`

> **注意版本匹配**：这条协议从 LEN=3（单个温度）改成了 LEN=4（温度区间）。
> 固件只采信 LEN=4 的帧，所以**旧版 App 配新版固件会显示 `NO DATA`**，两边要一起更新。
> 长度不对的帧会被状态机整帧吃掉，不会漏进指令通道触发动作。

**为什么不用文本**：单字节指令通道是"收到一个字节立刻执行"，多字节文本里每个字节都会被当成命令。
比如 26℃ 编码成 66，正好是 ASCII `'B'` = "后跳"，天气发下去宠物会跳起来。
所以天气必须走带帧头的独立通道，由 `Weather_OnByte()` 把整帧收完再解析。

### 语音说「天气」时的自动同步

桌宠没有联网能力，天气只能由手机取，所以语音链路是这样接的：

```
语音模块 --UART1: 0x51--> STM32
STM32 --USART3: 0x57--> 蓝牙模块 --FFF1 通知--> 手机
手机：定位 → 请求 Open-Meteo → 组帧
手机 --FFF2 写入--> 蓝牙模块 --USART3--> STM32
STM32：Weather_Valid=1 → Face_Config 每 30ms 重绘 → 屏幕出现天气
```

板子往手机发的只有一个字节：

| 方向 | 字节 | 含义 |
| --- | --- | --- |
| 板子 → 手机 | `0x57` | 请求同步天气（固件 `WEATHER_REQ_SYNC`） |

几个要点：

- **不阻塞等待**。发完请求立刻切到天气表情，手机取数据大约 2～4 秒，
  这期间屏幕显示 `NO DATA` 或上一次的旧数据，帧一到下一个 30ms 周期就刷新。
  如果在中断里等蓝牙，整个调度器都会停摆。
- **手机必须连着、App 得在运行**。没人接这个请求时，屏幕会停在 `NO DATA`。
- 上一次同步没结束时再触发会被忽略（`weatherBusy`），连说三次不会发三次请求。
- `0x57` 特意选在指令白名单（`0x29~0x39 / 0x40~0x49 / 0x50 / 0x51`）之外，
  万一蓝牙模块回显这个字节，也不会被当成动作指令。
- 只在**语音通道**触发。App 里的「显示天气」按钮发的是 `0x51`，不会联动同步；
  想换数据请按「同步天气」。

### 数据来源

[Open-Meteo](https://open-meteo.com/) —— 免费、不用注册、不用 API Key。

### 隐私

定位只在按「同步天气」时读一次，用来把经纬度发给 Open-Meteo 换天气，
不保存、不上传到别的地方。

### 中文字库

`OLED_CF16x16` 原本只有 `，。你好世界` 6 个字，这次新增了 17 个：

```
晴 天 气 多 云 阴 小 中 大 雨 阵 雷 雪 雾 温 度 湿
```

SimSun 14px 渲染，每字 32 字节，共约 600 字节。（12px 只占 12 个像素高，看起来比数字矮一截，所以改成了 14px。）

> **加新字时注意**：数组末尾有一个 `""` 哨兵项，`OLED_ShowChinese()` 遍历到空字符串就停止。
> 新字必须插在哨兵**之前**，插在后面等于没插（会显示成方框问号）。
> 生成脚本在 `tools/gen_glyphs.ps1`。

## 七、容易踩的点

- **移动类指令是持续的**：按了"前进"它就一直走，直到你按别的（比如"直立"）。
  这是固件里蓝牙通道 `Sustainedmove=1` 的设计。
- **摇尾巴 / 显示电量 是开关**，按一次开、再按一次关。
- **调速是循环的**，按到最快再按会回到最慢。
- **写入失败**：日志会显示"写入失败（GATT 忙或连接已断）"。BLE 两次写之间需要
  间隔，连点太快可能丢一条，等一下再按。
- 手机和模块的有效距离通常 10 米以内，中间隔墙会掉。

## 八、重新编译

```powershell
cd AndroidApp
powershell -ExecutionPolicy Bypass -File build_apk.ps1
```

脚本不依赖 Gradle / Android Studio，直接用 SDK 里的 `aapt` + `d8` + `apksigner` 打包。
会自动搜索以下工具：

| --- | --- |
| 编译 Java | 带 `javac` 的 JDK 8 |
| 打 dex / 签名 | Java 11 及以上的运行时 |
| 资源 / 对齐 | Android SDK `build-tools` |
| 框架 | Android SDK `platforms/android-35` |

本机自动匹配到的：

## 十、改指令表

所有按钮都在 `MainActivity.java` 顶部：

```java
private static final Cmd[][] GROUPS = {
    { new Cmd("放松趴下", ')'), ... },
    ...
};
```

加一个按钮就是在对应数组里加一行 `new Cmd("名字", '指令字符')`，
按钮会自动排版（每行 4 个）。前提是固件里 `Command_IsValid()` 白名单允许这个字节。

如果要换模块，改这两个常量即可：

```java
private static final UUID UUID_WRITE  = UUID.fromString("0000fff2-...");
private static final UUID UUID_NOTIFY = UUID.fromString("0000fff1-...");
```
